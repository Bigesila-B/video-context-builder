# 示例一：30 秒短视频（standard 模式）

场景：用户丢来一段 30 秒的短视频，问「这段视频里发生了什么？」
目标模型只支持图片输入。

---

## 1. 先探一下视频底细

```bash
python scripts/probe_video.py short_30s.mp4
```

输出：

```
路径      : short_30s.mp4
时长      : 30.00 s
帧率      : 30.0 fps
分辨率    : 1920x1080
音轨      : 有
总帧数    : 900
探测方式  : ffmpeg-fallback        # 没装 ffprobe 时自动退化为解析 ffmpeg 输出
```

---

## 2. 生成视频上下文包

```bash
python scripts/build_video_context.py \
    --video short_30s.mp4 \
    --mode standard \
    --stt \
    --max-tokens 50000 \
    --out out.json
```

进度输出（stderr）：

```
[1/6] 元数据: 30.00s, 30.0fps, 1920x1080, 音轨=有
[2/6] 模式: standard —— 总览图 + 关键秒图，最多 96 帧，默认开 STT（大多数场景）；STT=开
[3/6] 产物目录: .../out_assets
[4/6] STT 转写中（faster-whisper / small）…
      -> ok (7 段)
[5/6] 采样计划: 总览 10 帧 / 1 张（间隔 3s）+ 秒图 10 张（6 帧/张）
      预估 token: 图像 7898 + 文本 285 = 8183 / 上限 50000
      ! token 估算 8183 <= 上限 50000（占比 16%，帧 70/96）
[6/6] 抽帧与拼图中…
      -> 总览图 1 张（10 帧）
      -> 秒图 10 张
完成，用时 3.2s -> out.json
```

**关键点**：30 秒里有 900 帧，我们只抽了 70 帧 —— 总览 10 帧负责「定位」，
10 张秒图（每张 6 帧）负责「看清」关键时刻。这就是分层策略。

---

## 3. 看产物

```
out_assets/sheets/
  overview_00_0s.jpg          # 4x4 总览图，10 格，标签 #001 00:00 … #010 00:27
  second_0000_1s.jpg          # 秒图：第 1 秒，3x2 六帧
  second_0001_4s.jpg
  ...
  second_0009_28s.jpg
```

总览图长这样（每格左下角是时间戳）：

```
┌──────────────────────────────────────────────────┐
│ OVERVIEW #1  00:00 - 00:27  (3s/sample)          │
├────────┬────────┬────────┬────────┤
│#001 00:00│#002 00:03│#003 00:06│#004 00:09│
├────────┼────────┼────────┼────────┤
│#005 00:12│#006 00:15│#007 00:18│#008 00:21│
├────────┼────────┼────────┼────────┤
│#009 00:24│#010 00:27│        │        │
└────────┴────────┴────────┴────────┘
```

秒图长这样（同一秒内的 6 帧，阅读顺序 左→右、上→下）：

```
┌────────────────────────────────────────────┐
│ SECOND SHEET 00:04 - 00:05 (6 frames / 1s) │
├──────────┬──────────┬──────────┤
│#001 00:04│#002 00:04│#003 00:04│
├──────────┼──────────┼──────────┤
│#004 00:04│#005 00:04│#006 00:04│
└──────────┴──────────┴──────────┘
```

`out.json` 里 `second_sheets[0].frame_timestamps` 形如：

```json
[4.0, 4.167, 4.333, 4.5, 4.667, 4.833]
```

这些时间戳不是「起点 + i/帧率」算出来的，而是 ffmpeg `showinfo` 报出的**真实 pts**，
所以跟画面严格对齐（可用测试视频内嵌的时码逐帧核对）。

---

## 4. 组装请求发给目标模型

```python
import json, base64, pathlib

ctx = json.loads(pathlib.Path("out.json").read_text(encoding="utf-8"))

def data_url(p):
    b = pathlib.Path(p).read_bytes()
    return "data:image/jpeg;base64," + base64.b64encode(b).decode()

content = [{"type": "text", "text": ctx["prompt"]}]
# 顺序必须与提示词里的「材料清单」一致
for s in ctx["overview_sheets"] + ctx["second_sheets"]:
    content.append({"type": "image_url", "image_url": {"url": data_url(s["path"])}})

# 把 content 发给你的多模态模型即可
print(f"共 {len(content) - 1} 张图，估算 {ctx['token_estimate']['total']} tokens")
```

模型看到的提示词开头是：

```
你是一个视频理解助手。
你没有直接看视频，只能看到按时间顺序排列的关键帧拼图、秒图和音频转写。
每张秒图对应视频中的 1 秒，包含多个按时间顺序采样的帧。
阅读顺序：从左到右，从上到下。
请遵守：
1. 只基于提供的材料回答；
2. 引用时间戳，例如 [00:12:30]；
3. 不确定时说明“抽样帧中未看到”；
4. 区分画面信息和音频信息；
5. 不要编造未出现的情节。
...
```

于是模型的回答会是「[00:12] 画面里出现了 XX，同时 [00:12-00:15] 的转写提到 YY」这种**带时间戳、可核对**的形式，
而不是模棱两可的「视频大概讲了什么」。

---

## 5. token 超了怎么办

假设改成 `--max-tokens 8000`，程序不会硬发，而是：

```
! 为把 token 压到上限 8000 以内，秒图数量已从 10 张自动下调到 6 张。
  如需更多细节：提高 --max-tokens，或用 --range 聚焦某段时间。
! token 估算 7802 <= 上限 8000（占比 98%，帧 46/96）
```

或者你想要「只看 10-15 秒」：

```bash
python scripts/build_video_context.py --video short_30s.mp4 \
    --mode custom-range --range 10-15 --out seg.json
```

只处理这 5 秒，逐秒出秒图，token 极少。

---

## 6. 无音轨的情况

把 `--stt` 去掉也一样：程序探测到 `has_audio=false` 会**自动跳过** STT，
`out.json` 里：

```json
"transcript_info": {"status": "skipped", "reason": "视频无音轨，已自动跳过 STT", ...}
```

不会报错，提示词里也会写明「无音频转写」，模型不会去编造声音内容。
