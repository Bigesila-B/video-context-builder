# 自适应采样和预算

`auto` 是默认入口；`adaptive` 是显式同义入口。其他命名模式保留传统行为。
以下是启发式起点，不是视频理解质量的实验最优参数。

| 有效区间时长 | 总览目标间隔 | 代表时长的自动总预算 |
|---|---|---|
| 最多 1 分钟 | 0.5 秒 | 30 秒 7k，60 秒 8k |
| 1–5 分钟 | 1 秒 | 5 分钟 11k |
| 5–20 分钟 | 2 秒 | 10 分钟 14k，20 分钟 18k |
| 20–60 分钟 | 4 秒 | 60 分钟 29k |
| 超过 60 分钟 | 8 秒 | 逐渐增加，最多 40k |

自动总预算公式（秒）：

```text
ceil_to_1000(4000 + 2200 * sqrt(span / 30))，限制在 6000–40000
```

指定 `--range` 时以有效区间时长安排预算和密度，而非原片时长。
显式 `--max-tokens` 覆盖公式。预算、源帧率、分辨率和帧上限都可能迫使实际间隔大于目标。

## 分配与最终复核

默认预留总预算的 10% 为估算余量、15% 为后续补看；回答预留约 10%，最少 256、最多 2048。
这三个部分从总额扣除，得到单次主请求材料的 `input_limit`。
`--response-tokens / --safety-ratio / --revisit-ratio` 可调整预留。

例如 12000 总预算：安全 1200、补看 1800、回答 1200，当前输入最多 7800。
预留没有发给目标模型，不等于已经产生消耗。后续调用必须由调用方维护累计使用记录。

所选转写原文约占输入限额的 22%，仍受 `--max-transcript-chars` 限制；完整原文另存 JSON，时间戳不改写。
图像规划扣除文本和提示词余量；先保护总览，再分配局部图。局部图在时间分区内优先场景变化、问题关键词和语音起点。
没有检测到事件也会均匀补点。不是光流检测或语义理解。

按实际图片尺寸、实际提示词和原图再次估算。超限时先减原图/低优先级局部图，再在全程分散保留总览帧。
固定提示词本身太长或无法容纳任何画面时标记 `ready_to_send=false`。
`--no-degrade` 用于检查未经预算削减的目标材料，超限仍如实标记。

## 成本与覆盖的边界

- 图像预设是近似估算，不是供应商账单；10% 安全余量没有统计误差保证。
- 拼成一张图仍按像素/目标模型规则估算，不能把一张拼图视作“一次固定费用”。
- `budget.allocation.scope` 为 single_request；只针对按 README 顺序发送的主包。
- 分段 map 路线另报累计输入，重复图片重复计数；输出和 reduce 还会增加用量。
- 最大采样间隔报告以实际采样时间点计算；视频中存在短事件时应补看相邻时间窗。
- 预算很低或视频很长时只有稀疏定位证据，不能声称连续观察过全片。
- 目前没有自动模型调用、自动补看、多轮累计账本、OCR 或光流；这些能力由后续扩展/外层调度提供。
